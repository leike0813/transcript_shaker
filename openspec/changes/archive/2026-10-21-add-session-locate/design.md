# Design

## Context

见 `proposal.md`。约束：脚本零安装、任意 cwd 可运行；候选池 6000+ 文件，定位不能解析内容；`--list` 输出由 LLM 阅读后取路径。

## Goals / Non-Goals

**Goals:**

- 一条命令列出最近候选，输出形状稳定、可排序。
- 扫描目录与 `SKILL.md` 支持矩阵一致。

**Non-Goals:**

- 不做会话内容摘要、标题提取或全文搜索。
- 不解析候选文件来判断 harness；harness 由路径归属决定，内容识别仍由 `detect_adapter` 在转写时完成。

## Decisions

**1. 用 `--list` 标志而不是子命令。** 现有入口是单命令 + 位置参数；加一个互斥标志改动最小，Agent 只需记住一条调用形式。备选 `locate` 子命令会引入子命令解析和文档分叉，收益不足。

**2. 只 stat，不读内容。** 候选池 6000+，逐个解析会慢一个数量级；标题/首条消息对“选文件”没有决定性帮助，时间与路径已足够。代价是无法过滤损坏文件，写入易错点。

**3. 输出 TSV 而不是 Markdown 表。** LLM 直接按行取路径，TSV 没有转义问题；路径含 tab 的情况可忽略。首行固定 `# candidates: N`，无候选时也输出，便于脚本判空。

**4. 扫描表放代码，`SKILL.md` 保留同一矩阵。** 代码是扫描行为的真源，文档是 Agent 的使用契约；用测试锁定两边 harness 集合一致，避免遗漏。备选“文档只写 `--help`”会让 Agent 在不运行命令时无法判断目录范围。

**5. `--limit` 在渲染前截断。** 首行计数与实际输出行数一致，避免“总数 50、只显示 20”的歧义。

**6. 参数错误用 argparse 的退出码 2。** 与文件/格式错误（1）区分，便于 Agent 判断该改参数还是改文件。

## Risks / Trade-offs

- **mtime 不等于会话时间**（codex 归档压缩、文件被复制）→ `SKILL.md` 明确提示看文件名时间戳；不为此引入内容解析。
- **扫描表与真实目录布局漂移**（harness 升级改路径）→ `--list` 无候选时输出 `# candidates: 0`，Agent 回退到用户给路径；矩阵集中在 `locate.py` 一处，改一行即可。
- **`--list` 列出子代理文件**（omp/kimi 的子目录是否命中由 glob 决定）→ 当前 glob 只匹配主会话；子代理仍可显式传路径。
